# 通知

通知は契約内容を自動変更せず、本人が確認するための情報を提供します。

## 対象と設定

設定の「通知」（`/settings/notifications`）とヘッダーの通知ベルから、更新・年払い・無料期間終了・値上げ候補・取り込みエラー・新しい確認待ちの6種類を設定できます。種類別にアプリ内・メール・Pushを選び、メール送信とPush送信への同意は独立して保存します。Pushは初期OFFです。一方の同意を取り消しても、もう一方の設定は変わりません。通知日数は0〜30日前、時刻と期間の境界は日本時間（Asia/Tokyo）です。日数・時刻は確認待ち以外へ適用します。

メール送信には、本人による明示的な同意、種類別のメール通知設定、Clerkの署名付きWebhookで同期した本人の検証済み宛先、管理者が登録した送信元と有効なResend資格情報が必要です。宛先や資格情報は暗号化保存し、ジョブやログへ含めません。送信設定が利用不能になった場合も、本人はメール通知への同意を取り消せます。

Push送信には、本番環境の有効なOneSignal設定、本人のPush送信への同意、種類別のPush設定、受信確認済みの端末が必要です。メールの宛先確認やメール同意ではPushを有効化しません。管理者の準備は[初期設定](setup.md#任意設定onesignalとpwa)を参照してください。

## PWAと端末の受信確認

1. HTTPSの本番サイトでログインし、設定の「通知」を開きます。設定を開くだけではSDKを読み込まず、許可も要求しません。
2. Push送信への同意と必要な種類のPushを保存し、「この端末でPush通知を有効にする」で準備します。
3. 準備後の「この端末の通知を許可する」を押し、ブラウザーの許可を選びます。拒否した場合は、ブラウザーまたはOSのサイト通知設定を変更してから再操作してください。
4. 確認通知を受信するか、その通知を開きます。Cycrioが受信を確認し、端末一覧が「受信確認中」から「有効」になったことを確認します。OneSignalが送信を受け付けただけでは有効になりません。

iPhone・iPadはiOS/iPadOS 16.4以降が対象です。共有メニューから「ホーム画面に追加」し、追加したアイコンからWebアプリとして開いて同じ操作を行います。通常のブラウザータブではPush許可を要求できません。「Webアプリとして開く」が表示される場合はONにします。Cycrioのmanifestは`id: /`、`scope: /`、`display: standalone`を固定しています。OSごとの条件は[OneSignalのiOSガイド](https://documentation.onesignal.com/docs/en/web-push-for-ios)を参照してください。

受信確認はサーバーでチャレンジを作成してから5分で失効し、誤った確認は最大5回までです。登録APIは非機密の`expires_at`を返し、画面はこの期限内の受信証明を確認します。端末一覧APIは有効なチャレンジがなくなった未確認端末を`expired`として表示します。これは表示用の状態で、DBの端末状態を新しく追加するものではありません。確認通知が届かない場合は端末一覧を再取得し、期限切れの案内を確認してから「この端末でPush通知を有効にする」で再開始してください。登録結果不明時に自動で登録要求を繰り返しません。登録応答自体が失われ期限を確認できない場合も、一覧から対象端末を停止してから本人の操作で再開始します。通常通知は受信確認済み端末だけへ、一般的な文面と認証が必要な画面へのリンクを送ります。メール原文・件名・送受信者・契約の個人情報は通知本文へ含めず、Clerk IDやメールアドレスをOneSignalの外部ユーザーIDとして設定しません。

端末一覧の「この端末の通知を停止」で該当する登録を停止できます。ログアウト・確定した認証終了・別アカウントへの切替でも旧登録を停止します。通信障害で停止できない場合は「端末停止を再試行」を実行してください。停止待ちが残る間は新しい有効化を開始できません。別アカウントでは改めて本人の操作と受信確認が必要です。通常の認証トークン更新や設定画面からの移動では停止しません。

ブラウザーやOSで通知を拒否・許可リセットした場合は、再読込・一覧再取得・画面復帰時にネイティブの許可状態を読み取り、このブラウザーに本人の解除証明がある端末だけを停止します。この確認ではSDKを読み込まず、通知許可も要求しません。他の端末は維持します。SDK読込の通信エラーが確定した場合は一覧再取得後に有効化を再試行できます。読込タイムアウトや初期化の成否が不明な場合は画面の案内に従ってページを再読み込みしてください。

メール・Pushの準備ができていない場合も、既存の同意と種類を維持したまま他方の停止、種類の縮小、アプリ内設定の変更を保存できます。準備を必須とするのは、そのチャネルへの新規同意と通知種類の追加です。通知時刻と何日前から通知するかは配信タイミングの設定として扱います。

固定SDKとroot workerはビルド時に生成されます。独自のオフラインキャッシュは持たず、PWAへの追加はオフラインでの利用を保証しません。

## 新しい確認待ちのまとめ通知

メール解析が完了すると、新しく確認が必要になった候補を解析実行ごとにまとめて通知します。既存Workerが通常は約1分間隔で観測し、通知時刻の設定まで翌日に遅らせません。件数は通知作成時点の新規グループ数で、現在の未解決件数とは異なります。

導入前の既存候補、設定を有効にする前に完了した同じ出来事、同じメールの同じ意味の再解析は遡って配信しません。新しいメールや意味が変わった解析結果は区別します。送信前にその集約の元情報がすべて登録・除外・予約済みになるなどして対象外になった場合は送信を抑止します。別の古い確認待ちが残っていることだけでは送信しません。

## 生成と配信

通知の生成と配信はWorkerが実行します。通知の事実は不変とし、既読状態と対象外になった状態を別に管理します。アプリ内・メール・Pushはそれぞれ配信台帳を持ち、通知対象の同じ出来事を重複登録しません。

Hatchetへ渡すのは配信IDとlease IDだけです。未送信の準備が中断された場合は、1分のlease期限後に再取得できます。送信直前に本人の有効状態・最新の通知設定・契約や元情報と、メールの検証済み宛先・Resend資格情報、またはPushの端末・App ID・OneSignal資格情報を確認し、関連する変更とDBロックで直列化します。最終確認で送信予定時刻が未来になった場合は、通信せず待機へ戻します。

外部通信前に「結果不明」を永続化し、同じ通知に対して外部通信を繰り返しません。受付応答の消失・送信途中の停止・結果保存の失敗でも自動再送しません。失敗・抑止済みの同じ通知も再送しません。

メールの再解析で値上げ候補の参照先が変わっても、同じ元メール・契約・通貨・値上げ後料金の通知を再送しません。まだ送信を始めていない配信だけは、配信IDを維持したまま現在の候補へ引き継ぎ、旧leaseを無効にします。

## 配信結果

送信の受付は、宛先への到達を意味しません。配信・バウンス・迷惑メール報告などは既存の署名付きResend Webhookから最小限の事実を保存し、本人の配信詳細へ表示します。Webhookが受付応答より先に届いた場合や同じイベントが複数回届いた場合も扱えます。他のユーザーの通知や配信結果は照会できません。

| Pushの状態 | 意味 |
| --- | --- |
| `accepted` | OneSignalが受付IDを返した状態。「Push送信受付済み（配信未確認）」と表示し、実端末への到達証明にはしません。 |
| `unknown` | 応答消失・通信障害などで受付を確定できない状態。重複防止のため自動再送しません。 |
| `failed` | OneSignalの明示拒否など。今回送信した購読のうち無効と確認されたものは停止します。 |
| `suppressed` | 同意・元情報・端末・資格情報などが条件を満たさず、送信しなかった状態。 |

端末登録時の受信確認はその端末への確認通知の証明です。その後の通常Pushの到達履歴を証明するものではありません。PushについてResend Webhookの配信・バウンス状態は使いません。

## 検証と運用

`make check`、`make test-integration`、`make test-web-browser`で生成・設定・配信管理とPC／モバイルの操作を検証します。合成SDK/APIのブラウザー検証は実OneSignalへ送信しません。`make smoke`は基盤の疎通確認です。実メール送信、DNS設定、外部Webhookの到達確認は別途受入確認してください。

OneSignal App ID/App API keyと本人の実機を用意した後、次の受入確認を行います。合成試験の成功だけで本番配送やOS通知表示の成功としません。

- PC・Androidの対象ブラウザーとiPhoneのホーム画面アプリで、初回の明示許可・拒否時の案内・確認通知の受信・端末の「有効」への変更を確認する。
- 背景・終了状態で通常通知を受け取り、クリック後のログインと対象画面への遷移、ロック画面の一般文面を確認する。
- 端末停止、Push同意OFF、ログアウト、多タブのアカウント切替後に旧アカウント宛ての新しい配信が行われないことを確認する。停止した端末の再登録では受信確認をやり直す。
- 同じAppでの鍵更新、資格情報の無効化、App変更時の再読込・端末再登録を確認する。
- 新しいメールの解析完了で新着だけがまとまり、再解析や過去の候補で通知が増えないことを確認する。メール同意とPush同意の独立も確認する。

初期設定は[設定ガイド](setup.md)、本番構成・Webhook・復旧は[運用ガイド](operations.md)を参照してください。
