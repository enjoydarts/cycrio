# 初期設定ガイド

[READMEへ戻る](../README.md)

アプリにログインするための設定、運用者によるAI・OAuthアプリの準備、本人によるメール接続の順に進めます。起動方法は[README](../README.md#ローカルで起動する)を参照してください。

## 1. Googleログインと利用許可

ClerkでCycrio用の開発インスタンスを作り、Googleログインだけを有効にします。メールOTP・パスワード・電話などのログイン方法はClerk側でも無効にしてください。

```sh
make configure-auth
```

対話入力するのはClerkの**Publishable Key**とフロントのoriginです。標準のoriginは`http://localhost:3100`です。ClerkのSecret API Keyは不要です。

設定はGit対象外の`.local/bootstrap.json`に保存され、APIとWorkerが再起動します。APIは設定したClerkインスタンスの公開JWKSでセッションを検証します。

WebでGoogleログインすると、初回は利用許可待ちになります。表示される本人のClerkユーザーIDを使い、最初の管理者を許可します。

```sh
make grant-admin USER_ID=user_example
```

`user_example`は実際のClerkユーザーIDへ置き換えてください。利用許可を再確認すると、管理者用の設定が表示されます。最初にアクセスした人へ自動で管理者権限を与える仕組みはありません。

利用者の追加・停止も運用CLIから行います。

| コマンド                                 | 内容                     |
| ---------------------------------------- | ------------------------ |
| `make allow-user USER_ID=user_example`   | 一般ユーザーの利用を許可 |
| `make revoke-admin USER_ID=user_example` | 管理者権限を解除         |
| `make disable-user USER_ID=user_example` | 利用を停止               |

アプリへのGoogleログインは、Gmailの読み取り同意を代替しません。

退会時のClerkユーザー削除には、管理者の「APIキー」でClerk Backend APIのSecret Keyを登録し、「外部連携」で同じインスタンスIDを設定します。Webhook署名鍵とは別のキーです。Secret KeyはDBへ暗号化保存し、環境変数には追加しません。未登録・無効化・Clerk障害時もCycrio内の削除は進み、Clerk側は設定復旧後に再試行します。詳細は[退会とデータ削除](user-erasure.md)を参照してください。

## 2. 管理者がAIを準備する

管理者設定は、一般ユーザーからは操作できません。設定を保存するだけでは有料の接続テストを実行しません。

| 画面                               | 役割                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| APIキー `/settings/credentials`    | 使用するAIサービスのキー、メールOAuthアプリ、Webhook署名鍵の登録・更新・無効化 |
| モデルカタログ `/settings/catalog` | モデル一覧の同期、価格と変更履歴、価格調査、モデルの整理                       |
| AI の準備・送信許可 `/settings/ai` | モデル・料金・実行条件の保存、接続テスト、有効化、送信許可の確認               |
| AI 利用原価 `/settings/usage`      | 月別・使用ユーザー別・メール接続別の内訳と呼び出し履歴                         |

### APIキーとモデル一覧

「APIキー」で、一次判定に使うLiquid AIと、二次処理に使うOpenRouter / OpenAI / Anthropicのキーを登録します。未使用サービスのキーは不要です。秘密値は暗号化してDBへ保存され、平文では再表示できません。AIキーは`.env`へ記載しません。

モデル一覧と価格は管理画面のカタログから扱います。

| プロバイダー                   | 現在の取得・管理方法                                       |
| ------------------------------ | ---------------------------------------------------------- |
| OpenRouter                     | 公開Models APIからモデル情報・価格を同期                   |
| OpenAI / Anthropic / Liquid AI | 登録したAPIキーでモデル一覧を同期。APIにない価格は別途管理 |

「価格調査」では、調査に使うプロバイダーとモデルを指定し、Web検索テストを確認してから公式情報に基づく価格調査を実行できます。手動の価格設定にも対応しています。モデルや価格の変更は履歴に残り、過去の価格版を上書きしません。

OpenRouterを除く対象プロバイダーのモデルは、20件で打ち切らず全候補を最大16モデルずつまとめて調査します。検索1回と必要に応じた公式ページ閲覧を指示し、OpenAIのツール処理は最大2回、Anthropicの検索は最大1回です。調査の中でテキスト生成かを確認し、対象外や判別保留では通常テキスト料金を保存しません。モデルAPI同期から追加の有料調査は起動せず、定期調査は設定した実行間隔に従います。調査モデルの候補は全ページを裏側で取得し、検索で選べます。詳細は[モデル料金の全件調査](price-research.md)を参照してください。

価格不明と0円は別の状態です。参考価格を保存しても、過去の実利用原価は書き換わりません。価格調査・接続テストは外部APIの利用料金が発生する操作として確認してください。

### 接続テストと有効化

1. 「AI の準備・送信許可」の「モデル・料金」で一次・二次モデルを選びます。
2. 配信先・価格・実行条件を確認し、下書きを保存します。
3. テスト送信と課金を確認して、合成メールによる接続テストを実行します。
4. 成功したテストの設定版を有効化します。
5. 本文の配信先と保持・学習利用条件を確認し、送信許可を設定します。

OpenRouterでは条件に適合する配信先を選び、OpenAI / Anthropicの直接接続ではそれぞれの保持・学習利用条件を確認します。一次のLiquid AIも含め、メールをCycrioに保存しないことと、外部AI側の保持条件は別です。

原価画面では取得できたプロバイダー報告額と、固定した価格版・使用量からの推定額を区別します。不明な料金は0円に変換しません。管理者のテストと利用者のメール処理も区別して記録します。

料金調査も、トークン料金と検索料金を合算してシステム処理の推定原価に含めます。古い調査の原価を再計算する手順と、不足データ・検索料金配賦の扱いは[料金調査の原価](price-research.md#調査にかかった原価)を参照してください。

## 3. メールOAuthアプリを準備する

Gmail / Google Workspace・Outlookを使う場合は、運用者が各サービスにOAuthアプリを作成し、「APIキー」画面のメール連携アプリへ**Client ID・Client Secret・Redirect URI**を登録します。本人の接続ごとにアプリの秘密値を入力する必要はありません。

| 接続                     | OAuthアプリの準備                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| Gmail / Google Workspace | Google CloudでGmail APIとOAuth同意画面を設定し、Web applicationのOAuthクライアントを作成                |
| Outlook.com / Hotmail    | Microsoft Entraで個人Microsoftアカウント向けのアプリを登録し、WebのリダイレクトURIとClient Secretを設定 |

| 接続    | 使用する権限                                             | ローカルのRedirect URI                                 |
| ------- | -------------------------------------------------------- | ------------------------------------------------------ |
| Gmail   | `https://www.googleapis.com/auth/gmail.readonly`         | `http://localhost:8090/v1/mail/oauth/callback/gmail`   |
| Outlook | Microsoft Graphの委任された`Mail.Read`と`offline_access` | `http://localhost:8090/v1/mail/oauth/callback/outlook` |

Redirect URIは**APIのURL**です。Webの`http://localhost:3100`ではありません。外部サービス側とCycrio側で完全に一致させてください。本番ではAPIのHTTPS公開originへ置き換えます。

Outlook接続は`consumers`エンドポイントを使うため、Microsoft 365の職場・学校アカウントは対象外です。Client SecretにはSecret IDではなく、発行された秘密の**値**を登録します。

Google側のテストユーザー・公開状態、Workspaceの組織内アプリ制御、同意とトークンの期限などは対象環境で確認してください。長期利用や公開に必要なプロバイダー側の準備は、アプリ内への資格情報登録だけでは完了しません。

## 4. 本人がメールを接続する

「設定」→「メール連携」から接続を追加します。管理者も、この画面では自分のメールだけを扱います。

- Gmail / Google Workspace・Outlookは、公式の認可画面で本人のメール読み取りを許可します。
- Fastmailは、完全なメールアドレスとメール用の専用アプリパスワードを登録します。
- IMAPはプリセットを選ぶか、公開サーバー名・ポート・ログイン情報を指定します。プロバイダーごとの準備条件は画面の案内に従ってください。

IMAPの接続先は993の暗黙TLS、または143の必須STARTTLSです。証明書とホスト名を検証し、localhost・プライベートIP・自己署名証明書には接続しません。

保存・認可後は接続を確認し、解析対象のフォルダーを選びます。「メールから取り込む」で期間と送信範囲を確認し、本文送信に同意して開始します。フォルダー名に個人情報が含まれる可能性もあるため、画面やログを共有するときは内容を確認してください。

## 5. 取り込み後の確認

接続したメールをサイドバーから選ぶと、その接続の取り込み履歴と集計を確認できます。取得済み・解析済み・処理待ち・候補・登録済み契約・失敗は別々に集計します。

抽出した候補は「確認が必要」から確認します。新規登録、既存サブスクへの紐付け、不要な候補の除外ができます。関連メールをまとめた確認や、一括選択・除外にも対応しています。

失敗分の再試行と、処理済みメールの再解析は取り込み履歴から実行します。再解析はメールを再取得してAIへ再送するため、再課金を伴います。結果不明の呼び出しは既に課金されている可能性があり、明示的な確認なしに再送しません。承認済み・除外済みなどの保護対象は、一括再解析で上書きしません。

自動取り込み由来のメールを個別に再試行した場合も、元の自動取り込み履歴にまとめて表示します。過去の復旧処理による再試行も、保存された元の処理結果への参照を辿れる場合は同じ扱いです。自動設定を更新していても元の設定世代に紐付け、再試行の取消では未送信分の直前の結果を表示します。

全文送信が許可された解析では、正規化した本文がLiquid `d1.1` の実エラー応答で確認した250,000バイトの上限を超える場合、一次判定を省略して既存の二次解析モデルへ全文を渡します。この場合の分類 `uncertain` は一次で判定できなかったことを表し、一次判定の成功や利用量を作りません。実際の二次呼び出しだけを本人の予算判定・原価記録の対象にします。本文を切り詰めることはなく、二次モデルの入力上限にも収まらない場合は失敗として扱います。250,000バイト以下でも、トークン数や指示を含めた上限に達する可能性はあります。一般の422エラーを再送・迂回するものではありません。

## 任意設定：ResendとWebhook

メール取り込みの開始にResendは不要です。「メール送信・外部イベント」では、管理者本人への固定テストメールと配信結果を確認できます。テストメールの準備には、Resend資格情報・送信元・ClerkインスタンスIDを登録します。本人の宛先は、署名付きClerk Webhook、またはClerk Backend APIキーを登録して「本人の確認済みメールを同期」から取得できます。後者は外部からのWebhook受信が不要なため、ローカル環境でも使えます。同期だけではメールを送信せず、確認済みのメインメール以外は宛先に使いません。

メール通知を利用する場合は、本人の通知設定でメール通知への同意と種類ごとのメール通知を有効にします。管理者以外の利用者の宛先自動同期や、Clerk側の停止・削除の自動反映にはWebhookを使います。時刻は日本時間です。宛先を任意入力することはできません。

Clerk / ResendのWebhookや宛先同期、暗号化鍵の保管は[運用ガイド](operations.md)を参照してください。

## 任意設定：OneSignalとPWA

Pushは既存の`CYCRIO_ENV=production`でのみ有効です。開発環境では「この環境ではPush通知を利用できません」と表示され、実OneSignalへの登録・配信は行いません。App IDやAPI keyのための環境変数は追加しません。実機受入はHTTPSの本番サイト`https://cycrio.com`で行います。

1. OneSignalでCycrio用アプリを作り、`Settings > Push & In-App > Web`から**Custom Code**を選びます。Site NameをCycrio、Site URLを`https://cycrio.com`の正確なoriginにします。`www`など別originと混在させません。[公式Custom Code設定](https://documentation.onesignal.com/docs/en/web-push-custom-code-setup)に従ってWebプラットフォームを保存します。
2. **Typical Siteは使用しません。** 固定SDKではTypical Siteのdashboard設定で初期化オプションが置き換えられるため、本人操作後の許可・自動prompt/welcome無効化をコードで管理するCycrioにはCustom Codeが必要です。自動再購読、自動prompt、welcome通知を有効にせず、管理画面の案内コードをHTMLへ追加しません。
3. 同じアプリの`Settings > Keys & IDs`でApp IDと**App API key**を取得します。Organization API keyや一覧のKey IDは使用しません。App API keyの値は作成・更新時だけ表示されます。[公式Keys & IDs](https://documentation.onesignal.com/docs/en/keys-and-ids)を参照してください。
4. Cycrioへ管理者でログインし、「設定」→「API キー」（`/settings/credentials`）→「OneSignal」を開きます。`App ID`と`API key`を別々の欄へ入力して保存します。既存の資格情報管理で暗号化・版管理・監査し、保存後の秘密値を再表示しません。通常利用者はこの画面を操作できません。
5. 本人が「設定」→「通知」（`/settings/notifications`）でPushへの同意と種類別設定を保存し、端末の準備・通知許可・受信確認を行います。手順と実機受入項目は[通知ガイド](notifications.md#pwaと端末の受信確認)に従ってください。

SDK版160800の原本・LICENSE・SHA256はリポジトリに固定しています。`npm` lifecycleとブラウザーfixtureがハッシュを検証し、`/vendor/onesignal/160800/`と`/OneSignalSDKWorker.js`を生成します。OneSignalのダウンロードZIPを手動コピーする必要はありません。root workerはローカルの固定`OneSignalSDK.sw.js`だけをimportし、独自のオフラインキャッシュを追加しません。

デプロイ後は`/OneSignalSDKWorker.js`と固定SDKのURLが認証・redirect・HTML fallbackを介さずJavaScriptのMIMEで返ること、`/site.webmanifest`が`id: /`・`scope: /`・`display: standalone`であることを確認します。iPhoneはホーム画面に追加したアプリから許可します。一般のSafariタブからの許可操作や、OneSignalの受付結果だけでは実機受入は完了しません。

### 鍵の更新・停止

同じApp IDの鍵更新は、「API キー」のOneSignalへ新しいApp API keyと同じApp IDを保存します。確認済み端末は維持します。OneSignalで別の鍵を作成し、Cycrioを更新して新しい配信を確認してから旧鍵を失効させると、切替中の障害を抑えられます。OneSignalの既存鍵を直接rotateした場合は旧値が直ちに使えなくなるため、Cycrioも更新してください。

CycrioのOneSignal資格情報を「無効化」するとPushの利用を停止します。再登録しても無効化した旧版は復活せず、旧版の端末を自動復活させません。App IDを変更した場合も旧Appの端末を停止します。ページを再読み込みし、本人が新しいAppで端末を登録・受信確認してください。送信結果が`unknown`となった過去の通知は、設定復旧後も自動再送しません。個別端末だけを止める場合は本人の通知設定の端末一覧を使います。
