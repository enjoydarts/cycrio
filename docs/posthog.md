# PostHog監視と利用状況

ブラウザーは公式 `posthog-js`、Go API・Hatchet Workerは公式 `posthog-go` を使用します。静的配信のSvelteKitにはNodeサーバーSDKを追加しません。例外収集に加え、Goの共通送信境界で運用・AI・認証済みAPI操作の数値を明示的に計測します。

## 設定

1. PostHogでプロジェクトを用意し、Project Tokenとリージョンを確認します。
2. Cycrioの管理者画面の資格情報設定でPostHogを選び、Project TokenとHostを登録します。Hostは `https://us.i.posthog.com` または `https://eu.i.posthog.com` を指定します。
3. 本番API・Workerに `CYCRIO_ENV=production` を設定します。`compose.production.yaml` と `compose.coolify.yaml` は設定済みです。未指定の開発環境ではDB設定が存在しても送信しません。
4. 本番用にビルドしたフロントを配信します。開発ビルドは送信しません。本番ビルドでもAPIから有効設定を取得できなければ送信しません。

Project TokenとHostは既存の資格情報管理によりDBへ暗号化保存し、更新・無効化を監査します。管理APIと画面は保存した値を再表示しません。**Project Tokenはブラウザーからの取り込みに使う公開用トークンです。** 有効な本番環境では `/v1/public/telemetry` がこのトークンとHostだけを公開します。個人APIキー・プロジェクト秘密APIキーは登録できず、ブラウザーへ渡しません。トークン用の環境変数は不要です。

無効化・更新はGoの30秒周期、ブラウザーの60秒周期で読み直します。両段階を合わせ、ブラウザーの新規収集への反映には通常最大約90秒を見込んでください。ブラウザーの設定取得失敗時は新規送信を停止します。すでに送信を開始したリクエストの取り消しや、受信済みイベントの削除は行いません。JavaScript SDKにはイベント再送を無効化する公開設定がないため、通信失敗後にSDKが保持する既送信イベントは、ログアウト・設定無効化後にも元の識別子で再送される場合があります。新しいログインユーザーへ識別子を付け替えず、同じイベントUUIDでの取り込み重複を避けます。

## 収集範囲とプライバシー

- フロント: 未処理例外、未処理Promise rejection、SvelteKitのクライアントエラー。共通経路で重複を抑止します。
- API: panicと5xx。監視の `/healthz`・`/readyz` の通常の異常応答は除外します。リクエストが中断済みで、記録された原因がすべて `context.Canceled` の場合も除外します。独立した障害・期限超過・原因不明・panicは引き続き収集します。
- Worker: Hatchetタスクのerror・panic、処理後にDBへ保存された主要な失敗、pollerの取得・投入・実行失敗。認証拒否・設定不足・利用上限など既知の業務結果は除外します。

初回Heartbeatは、HatchetがWorkerの登録と稼働を確認するまで最大60秒待ちます。起動中も `/readyz` は実際の準備状態を返します。60秒を過ぎても準備できない場合は通常の監視へ移り、障害を記録します。稼働開始後の監視間隔・DB確認・送信手順は変わりません。

例外の種類・技術的なメッセージ・原因チェーン・関数名・ファイル・行番号を残します。すべてを固定メッセージや伏せ字へ置き換えることはしません。処理名・実行環境・内部ユーザーUUIDも記録し、未認証・システム処理は固定の匿名識別子で扱います。

メールアドレス、既知形式のAPIキー・JWT・Bearer認証値、認証・Cookie・メール本文や件名などの機微フィールド値、入力データの埋め込み部分を送信前にマスクします。通常の技術的な識別子、引用されたプロパティ名、複数行の原因説明は保持します。例外へメール本文・解析結果・資格情報を埋め込まない実装を維持し、任意のオブジェクトやリクエスト本文・ヘッダー・Cookie・DOM・consoleを自動添付しません。技術メッセージ内のURLは資格情報・query・fragmentを除き、スタックの公開アセットURLはそのまま照合に使います。

ブラウザーは公式SDKのパーサーでスタックを処理し、実際に読み込まれた同一originのコードアセットに一致するファイルURL・関数・行列と`chunk_id`を保持します。Goはアプリに加え標準ライブラリ・依存パッケージのフレームも残し、ローカル利用者名を含む絶対パスをパッケージ相対表記へ正規化します。リクエスト中の変数・メール内容をスタックへ追加することはありません。

### 非公開ソースマップ

本番ビルドではhidden source mapsを作成し、公式PostHog CLIでJSへchunk IDを注入します。mapの`mappings`・`sources`・`sourcesContent`を確認し、注入後のJSとmapを非公開のCI artifactへ保存します。公開用buildからmapを取り除き、JSに公開`sourceMappingURL`が残らないことも検査します。

アップロードには、取り込み用Project Tokenとは別のPersonal API key（Error tracking: Write、Organization: Read）が必要です。GitHub Actions Secretの`POSTHOG_CLI_API_KEY`に登録してください。このキーはCIのアップロード処理だけに渡し、DBの取り込み設定・ブラウザー・公開アセットへ混ぜません。

本番準備でソースマップをアップロードした後、同じJS bytesを公開します。アップロード前後と公開直前にSHA-256で一致を確認し、キー不足・アップロード失敗・アセット不一致時は公開を停止します。ソースマップ自体は公開しません。Project IDと接続リージョンはビルドスクリプト内のプロジェクト設定で管理します。

アップロードは公式CLIの`event`モードを使い、マップを特定のリリースへ固定しません。変更のないchunkを複数のコミットで再利用したときに、リリースIDだけの違いでアップロードが衝突することを防ぎます。ソースの復元は各フレームの`chunk_id`で行い、公開対象のコミットはCI artifactのmanifestと`release.txt`で照合します。

API・Workerの内部では、公開エラーの文言を維持したまま元の原因を引き継ぎます。共通のエラー変換または診断への記録時に、例外を観測した位置のGoスタックを捕捉し、報告境界のスタックより優先します。APIの5xxには登録済みのrouteパターンとHTTP状態を付け、URLの実IDやqueryは含めません。原因チェーンは最大16件、各メッセージは2048バイトで制限します。

メール解析・取得・管理者接続テスト・料金調査・通知は、失敗結果をDBへ保存して正常にreturnする場合も、元の例外を処理単位の診断スコープへ記録します。バッチの子処理は別スコープとし、panicの原因を通常エラーより優先して集約します。認証拒否・停止・同意不足など既知の業務結果の除外と、同じ失敗の二重送信抑止は維持します。元例外が取得できない古い記録に限り、保存済み理由コード・対象試行のHTTP状態等を補足する経路へ戻ります。

外部APIでは、エラー応答のmessage・type・code・param、検証エラーの対象フィールド・制約値、HTTP状態・request IDを選択して保持します。例えば422の`string_too_long`では対象の`body.state`、上限文字数、送信文字数を記録できます。応答全文・成功したメール応答・`input`・任意のbody/headersは保存しません。既知の入力・指示・メール内容・認証値の部分echoも除去し、通信例外は元の型名と秘匿化した原因チェーンだけを残します。失敗の記録から外部呼出しを再送することはありません。

HeartbeatはDB判定・Worker確認・API確認・資格情報取得・外部POSTの失敗段階と、timeout等の固定分類、HTTP状態、検証済みSQLSTATEを安全な原因として残します。秘密のping URLは保持しません。過去に捨てられた応答詳細やスタックは復元しません。

ユーザー切替・ログアウトでフロントの識別子を解除します。Goは実際のHTTP送信を退会用共有ロック内で行い、停止・削除済みユーザーのUUID付きイベントを送信しません。PostHog上で受信済みの過去イベントはこのローカル削除処理の対象外です。

Session Replay、クリックなどの自動イベント、パフォーマンス計測、Web Vitals、サーベイ、人物プロファイル生成は無効です。ページビューと離脱は下記の許可リストで手動送信します。PostHogプロジェクト側でもIP匿名化とReplay・自動イベントの無効化を設定してください。

### ページビューと離脱

本番フロントでは初回表示とSvelteKitの画面遷移で `$pageview`、次画面への遷移・`pagehide`・終了処理で `$pageleave` を送ります。同じ遷移通知や離脱通知の重複を抑止し、ブラウザーのキャッシュから戻った画面は新しい閲覧として扱います。

- 計測対象はホーム・メール・取り込み・契約・解析・レポート・管理・設定の既知の画面だけです。認証コールバックと未知のパスは送りません。
- 契約詳細は `/subscriptions/detail` へまとめます。実際の契約UUID・クエリ・ハッシュ・ページタイトル・参照元・入力値・DOMは送信しません。設定の別名URLは対応する固定画面へまとめます。
- ログイン中は内部ユーザーUUID、未ログイン時はホームだけをメモリ内の一時識別子で計測します。メールアドレスやClerkのユーザーIDを使わず、人物プロファイルは作りません。
- SDKのセッションUUIDと閲覧UUIDで閲覧・離脱を対応付けます。ログイン切替前の離脱は元のユーザーとセッションに紐付けます。CookieやlocalStorage・sessionStorageへのPostHogの永続化は無効です。未ログインの継続訪問や別ブラウザーとの同一人物判定は行いません。
- 滞在時間は表示から離脱までの経過秒数（最大24時間）です。操作中の時間だけを測るものではありません。離脱時はSDKのsendBeaconを使いますが、ブラウザー終了時の配信は保証されません。
- 無効設定・設定取得失敗中は送らず、再有効化後は現在の画面から計測します。過去の画面遷移を遡って再送しません。SDKが自動追加するプロパティも、送信前にアプリで構築した許可済み項目だけへ置き換えます。

PostHogのProject settingsのAuthorized URLsには、所有を確認した本番フロントのoriginを登録してください。`No live events` のヘルス警告は、実際の本番ブラウザーからページビューが届くことを確認します。初期表示・SPA・離脱の方式は[公式SPAガイド](https://posthog.com/tutorials/single-page-app-pageviews)と[滞在時間の説明](https://posthog.com/tutorials/time-on-page)を参照してください。

ページビューと離脱はProduct Analyticsのイベント枠を使い、1閲覧と離脱で通常2イベントです。既存の運用イベントも同じ枠へ加算されます。Web Analyticsの無料枠と単価は[公式料金](https://posthog.com/web-analytics/pricing)を確認してください。

## 障害時と検証

Goの送信は上限付き非同期キュー、2秒の送信期限、再送なしで処理します。同じユーザー・処理・分類・安全化済み例外とスタックが一致するときだけ1分間重複抑止し、異なる技術メッセージの例外をまとめて消しません。満杯や終了時の未送信イベントは破棄するbest effortであり、監査台帳には使えません。PostHogの通信失敗・設定取得失敗を本来のAPIやジョブへ返しません。

Workerの必須pollerでpanicが起きた場合は、例外を記録するだけで処理停止を隠しません。Worker全体のreadinessを不健康化し、通常の終了処理から終了コード1で停止して、既存のコンテナ再起動へ進みます。通常のジョブ失敗やPostHog自体の障害では、この停止処理を起動しません。

`make check`、`make test-integration`、`make test-web-browser` で単体・型・整形・ビルド・DB・画面を確認します。SDK送信境界のテストでは機密値を含む例外を使い、実際の送信JSONに残らないことを検証します。実プロジェクトへの疎通は個人データを含まない単発の合成例外で確認し、公開テストendpointや故意に失敗する処理を本番へ残しません。

処理プロセスの強制停止、DB内部で期限切れとして更新されるジョブ、通知生成内で保存後継続する個別失敗、Clerk削除の永続再試行結果は、現在のタスク境界だけではすべて収集できません。停止の検知にはHealthchecks.ioも併用します。

## 運用・AI・利用状況のダッシュボード

既存のProject Token・Hostと本番限定の設定を共用します。追加の環境変数・migration・DB接続の外部公開は不要です。Session Replay、自動収集、人物プロファイルは引き続き無効です。

| イベント | 単位 | 記録する情報 |
| --- | --- | --- |
| `cycrio_api_operation` | 許可リストにある認証済みAPIリクエスト | 固定操作名、成功・拒否・障害、HTTP状態、処理時間、内部ユーザーUUID |
| `cycrio_job_completed` | Workerタスクの実行 | 固定工程名、保存済み結果を反映した状態、経過時間、取得可能な所有者UUID |
| `cycrio_queue_snapshot` | 1分ごと・取り込み/解析それぞれ1件 | 待機run数、実行中run数、最古の未完了runの作成からの経過秒数 |
| `$ai_generation` | AI台帳の初回完了確定 | プロバイダー、モデルID、用途、利用区分、状態、判明している入出力トークン数とUSD原価、経過時間 |

API操作はログイン確認・概要・契約一覧・候補・解析結果の取得と、メール設定保存・接続テスト要求・取り込み要求・解析要求・契約登録/更新/ソース紐付け・候補却下が対象です。定期的な進捗照会、公開API、ヘルスチェックは除きます。操作名は登録済みrouteパターンから固定値へ変換し、実URL・query・実ID・本文を送りません。取得APIのリクエスト数は画面のクリック数ではなく、登録APIの成功回数は新規契約の純増数ではありません。

Workerはメールごとの件数やバッチ全体の完了件数ではなく、タスク実行単位です。結果を確認できない場合は `unknown`、新しい保存結果がない正常returnは `returned` とし、成功へ補完しません。解析では今回終了した項目を読み、失敗・不明を成功項目より優先します。

キューの数値は取り込み/解析のrun単位です。最古の経過時間には待機・lease取得済み・実行中を含みます。時間帯別のチャートはスナップショットの最大値であり、合計や現在値ではありません。読み取り失敗時には0を送信せず、その回のスナップショットを省略します。Workerが複数台の場合も、この最大値表示では重複したスナップショットを足し合わせません。

AI計測は初回完了のcommit後にだけ行います。料金調査のグループ、接続テスト、lease失効も対象とし、call単位の決定的なイベントUUIDで重複を抑えます。rollback・再完了・遅着原価・後日の原価訂正で呼び出し数を増やしません。trace IDには処理IDをそのまま載せず、名前空間付きUUIDへ変換します。モデルの表示名、メール識別子、プロンプト、応答本文、解析結果は送りません。

原価は**初回完了時点のスナップショット**です。`cost_known=true` の `cost_usd` だけを集計し、不明とUSD以外は別件数にします。使用量不明をトークン0へ補完しません。PostHogのAI Observability標準画面では独自の価格推定が表示される場合がありますが、Cycrioのダッシュボードの金額には使いません。正式な金額と月額予算判定には、訂正・遅着を反映するCycrioのDB台帳を使ってください。失効時の経過時間は外部APIの純粋な応答時間ではなく、呼び出し開始から失効確定までです。

チャートの再作成用クエリは `deploy/posthog/dashboard-queries.json` に保存します。運用・AI・利用状況の3つに分け、利用ファネルは同一ユーザーの「接続テスト成功→取り込み完了→契約登録API成功」を順序付き・7日以内で確認します。既存ユーザーや自動登録を含む全体の新規利用開始率を表すものではありません。管理者の操作も集計に含みます。集計日はPostHogプロジェクトのタイムゾーンに従います。

計測開始以前の成功履歴は遡って送信しません。キュー満杯・通信障害・設定無効化・停止時には計測が欠けるbest effortです。分析用キューは例外用と分離し、例外を優先します。PostHogの原価表示や分析値を監査台帳にしないでください。

### 無料枠内での運用

PostHogの組織のBilling画面で、Product Analytics・AI Observability・Error Trackingそれぞれの課金上限を `$0` にしてください。有料プランに登録済みの場合、無料枠があっても超過分には課金されます。上限に達した後のデータは欠落します。設定変更後は各製品の上限を再表示して確認してください。MCPの課金取得ツールは読み取り専用で、上限の変更には対応していません。

キュースナップショットはWorker1台あたり月約8.6万件（30日）です。API操作・Workerタスク・AI呼び出し・例外は実行量に応じて増えます。PostHogの月間無料枠は変更されるため、運用時に[料金表](https://posthog.com/pricing)と[課金上限の説明](https://posthog.com/docs/billing/limits-alerts)を確認してください。
