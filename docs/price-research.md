# モデル料金の全件調査

料金調査は、モデル一覧のAPI同期と別の管理者向け機能です。OpenRouterは一覧APIから価格を取得するため、Web検索による調査対象には含めません。OpenAI・Anthropic・Liquid AIのモデルは、有効・提供中・未削除の候補を20件で打ち切らず対象にします。テキスト入力に非対応と明示されているモデルは対象外です。モデル名や公開時期だけで種類を決めつけたり、古いモデルを自動的に削除したりしません。

## 調査と分類

モデルAPIだけでは種類を完全に判断できないため、公式情報の検索時に次の分類を確認します。

| 分類 | 扱い |
| --- | --- |
| テキスト生成 | 通常のテキスト入出力トークン料金を確認できた場合に採用 |
| 対象外 | 画像生成・音声・埋め込みなど、通常テキスト生成以外の価格は採用しない |
| 判別保留 | 種類の根拠を確認できないため価格を採用しない |

テキストのプロンプトを受け取る画像生成モデルを、テキスト生成として扱いません。マルチモーダルモデルでも、テキスト入力・テキスト出力とその料金を公式情報で確認できる場合は、そのテキスト料金だけを扱います。確認できない単価は0円にせず、不明のまま残します。公式出典、対象モデル、プロバイダーが一致しない結果も採用しません。

## 全件処理と中断時

調査開始時に対象一覧を固定し、同じ提供元の最大16モデルを1回のLLM問い合わせにまとめて処理を継続します。136モデルの場合は9回の問い合わせです。対象件数・処理済み件数・対象外・判別保留を記録し、全体の20件上限は設けません。

分類と価格は対象モデルごとに記録し、使用量と原価は実際の外部呼び出し1回につき1回だけ記録します。同じ問い合わせで調べたモデル数を原価に掛けません。途中でWorkerが停止した場合、送信済みの対象群は結果不明として自動再送せず、未着手の対象だけを継続します。設定やキーが変更・無効化された場合は新しい呼び出しを止め、遅着した原価は保持しながら、新しい設定へ古い価格を適用しません。

短い共通プロンプトで複数モデルの通常料金と分類を問い合わせ、長い解説は要求しません。同じ系列のモデルを近くに並べますが、名前から種類や価格を推定しません。検索1回と必要に応じた公式ページの閲覧を指示し、OpenAIのツール処理上限は2回、Anthropicの検索上限は1回です。OpenAIは2回とも検索になる可能性があるため、実際の検索回数を原価に計上します。検索コンテキストは`low`、対応するGPT-5・GPT-6系では推論量と出力の詳しさも`low`にします。出力の上限は4096トークンです。これらは入力トークン数の固定上限を保証する設定ではなく、実際の使用量はプロバイダーの応答で記録します。1回で確認できないモデルを、個別の有料問い合わせで自動的に調べ直すことはありません。

対応するOpenAIモデルではJSONスキーマで回答形式を指定します。結果はモデルごとに検証し、不正な項目と同じIDの重複項目を除外しながら、有効な他のモデルの結果を保存します。一部の問い合わせが失敗した場合は実行全体を一部失敗として記録し、確認済みの価格は保持します。未確認の価格が残る完了も画面で区別します。

手入力の価格上書きと過去の価格履歴は保持します。料金が同じでも公式情報を確認した事実を更新します。

## 調査にかかった原価

調査に使ったモデルの使用量と固定した価格版から、トークン料金とWeb検索料金を合算し、システム処理の推定原価として記録します。調べられる側のモデルの価格を、調査の実行原価には使いません。プロバイダー報告額がある場合は推定より優先します。検索回数が不明な場合は0回にせず、使用量や必要な単価が欠ける場合も原価不明のまま扱います。

Web検索の料金版は `web-search-2026-11-04` です。OpenAIの通常の`web_search`とAnthropicの`web_search_20250305`は、検索1,000回あたり10 USDをモデルのトークン料金に加算します。OpenAIの`gpt-4o-mini`・`gpt-4.1-mini`では、通常の検索の検索内容について1回あたり8,000入力トークンの固定料金も計算します。他のモデルの検索内容や推論トークンを、報告済みの使用量に重ねて加算しません。根拠は[OpenAI公式料金](https://developers.openai.com/api/docs/pricing)と[Anthropic公式検索料金](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)を参照してください。

料金調査のOpenAIリクエストはキャッシュ保持時間や個別のキャッシュ境界を指定しません。GPT-5.6・GPT-6系で書き込み総数だけが保存されている場合は、[公式の既定値である30分](https://developers.openai.com/api/docs/guides/prompt-caching)を計算用に補完し、通常入力単価の1.25倍の書き込み料金を適用します。元の使用量と価格版は変更せず、計算根拠の版に`+default-cache-30m`を付けて補完を区別します。未知のモデルや内訳が矛盾する場合に保持時間を決めつけることはありません。

過去分は次の管理CLIで再計算できます。外部APIへ調査を再送する操作ではありません。

```sh
docker compose run --rm --no-deps manage recalculate-research-costs
docker compose run --rm --no-deps manage recalculate-research-costs -apply
```

既定は確認だけで、`-apply`で保存します。再計算は終了済みの調査を対象とし、使用量・採用原価の元の履歴を残します。同じ条件で再実行しても重複計上せず、プロバイダー報告額を推定で上書きしません。呼び出し時の価格参照がない古い記録では、確認できるモデルの価格版を補完した推定として扱い、使用した価格版と補完の根拠を保持します。

個別の検索回数が残っている場合はそれを使います。実行全体の検索回数しか残っていない旧記録では、その検索料金を呼び出しへ配賦し、合計が元の検索料金と厳密に一致するようにします。配賦と個別の実測回数は区別して記録します。使用量そのものが残っていない呼び出しの全額を推測して埋めることはありません。

OpenAIの検索料金は`search`アクションを数え、`open_page`・`find_in_page`の未完了を追加の検索料金として扱いません。診断にはアクションの種類・状態、ツール上限、HTTP状態、応答状態、失敗コードだけを保持し、検索文や応答本文は保存しません。migration 42は旧共有呼び出しに当時のツール上限1を記録します。再計算では、旧記録の確認済み検索数がこの上限に達している場合だけ検索数を確定できます。新しい不正・矛盾した証跡を、この旧記録向けの補完で既知扱いにしません。

## 操作

「料金調査」に使うモデルはメール解析用のモデルと独立しています。候補は裏側で全ページ取得し、画面では検索で絞ってプルダウンから選びます。候補の20件ごとのページ切替は不要です。

設定を保存し、Web検索テストの成功を確認してから対象プロバイダーの調査を実行します。モデル一覧の同期だけで、有料のWeb検索テストを自動実行することはありません。自動調査を有効にした場合は、その設定に従って調査を実行します。

モデル一覧のAPI同期完了から、追加の有料調査を直接起動することはありません。定期調査は中央のスケジューラーが設定した実行間隔と次回実行日時に従って起動します。手動調査は、保存・Web検索テストの条件を満たしていれば定期間隔を待たずに実行できます。
