# PostHogダッシュボード実装計画

目的: 本文や資格情報を送らず、Cycrioの運用・AI・利用状況をPostHogで確認する。

方式: 既存の公式Go SDK、暗号化DB設定、本番限定・非同期送信・退会ロックを再利用する。ブラウザー自動収集、Replay、機能フラグ、アンケートの有効化は含めない。新しい依存関係やmigrationを追加しない。

- [x] `internal/telemetry/analytics_test.go`で、送信JSON・UUID・既知/不明の使用量と原価・開発環境停止のテストを先に失敗させる。送信障害は既存の共通境界のテストも再実行する。
- [x] `internal/telemetry/analytics.go`に型付きのAPI操作・Workerタスク・AI呼び出しの送信境界を作る。例外とは別の上限付きキューを使い、例外を優先する。
- [x] APIの登録済みrouteパターンを固定操作名へ変換する。本文、query、実ID、メールアドレスを計測引数に含めない。認証済み操作だけを対象にし、HTTP成功・拒否・障害を区別する回帰テストを追加する。
- [x] Workerの既存タスク境界に実行時間と結果を追加する。保存済み業務結果や結果取得失敗を成功へ変換しない回帰テストを追加する。
- [x] AI台帳の初回完了commit後だけ、型付きメタデータを送信する。料金調査のグループ内複数完了・再送・rollback・遅着は重複計上しない。退会ロックは既存の送信境界を共用する。DB統合テストで確認する。
- [x] PostHogの既存資料・カタログ・イベントを確認し、ネイティブ分析で3つのダッシュボードを作る。母集団、計測開始時点、best effortであることを記載する。
- [ ] `make check`、`make test-integration`、`make restart`で検証し、論理単位でcommit/pushする。本番デプロイと実イベント到達、ダッシュボードの実行結果を確認する。

集計上の注意: APIリクエスト数はクリック数や契約の新規作成件数とは区別する。Workerはタスク実行単位であり、バッチ全体の完了件数ではない。AI原価は初回完了時のUSD採用額のみで、不明・他通貨・後日の修正を0へ補完しない。正式な原価・予算判定はDB台帳を使用する。停止・キュー満杯・通信障害では計測が欠けるため、監査用途には使用しない。
